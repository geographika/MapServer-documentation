MS RFC 140: OGC Maps API Support¶

Status:

1. Overview¶

OGC Features API support was added in MS RFC 134: OGC API Support and documented at OGC API : Features.

The modular nature of OGC API means many parts of the OGC API are already implemented and are shared with the OGC Maps API such as landing pages, conformance, and collections. Links:

https://github.com/opengeospatial/ogcapi-maps - GitHub repository

2.1 Proposed Solution¶

WMS Facade

Lots of code in the mapwms.cpp file that is not required. Grouped layers, filters etc.

Either a cleaner version or construct a WMS request.. Cleaner version will have duplicated code. Move to smaller functions?

mapserv -v

"SUPPORTS=OGCAPI_SERVER" will remain unchanged. Services implemented will be listed at the landing page.

https://www.mapserver.org/ogc/ogc_api.html#metadata Remain the same. Additional items?

“ows_enable_request” “*” #REQUIRED

“wms_enable_request” “GetMap GetFeatureInfo”

if (msOWSRequestIsEnabled(map, NULL, “M”, “GetFeatureInfo”, MS_FALSE))

Formats:

https://mapserver.org/ogc/wms_server.html#web-object-metadata

Add a new WEB METADATA item similar to wms_getmap_formatlist

“wms_getmap_formatlist” “image/png,image/gif,image/png; mode=24bit,image/jpeg,image/vnd.wap.wbmp,image/tiff,image/svg+xml”

Use OUTPUTFORMAT names?

“oga_getmap_formatlist” “png,gif,tiff”

Add to list, or allow any value?

enum class OGCAPIFormat { JSON, GeoJSON, OpenAPI_V3, HTML };

Most setting of parameters from mapwms.cpp lines 1227 onwards

map->width == -1 || map->height == -1
map->outputformat
image->resolutionfactor

MS_NONSQUARE option

Turn all layers off except the collection

Legends? Styles?
